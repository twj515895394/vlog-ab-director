## 1. 两级验收与执行环境

先执行 node tests/qc-check.mjs，再用实际加载本 Skill 的语言模型输入 tests/live-validation-inputs.md 的请求。保存真实生成的完整 Prompt，按 [T06 QC](../references/quality_control.md) 人工/语义审阅；文本通过后，使用用户实际部署的 H3 Ref2VA 或 T2VA 模式分别生成每个独立 15s 任务。必须记录真实模型名称/版本、平台、日期、输入模式、采样设置（可见时）、随机种子（可见时）、实际上传顺序、Prompt 原文、输出文件或可访问链接；未知参数写 UNKNOWN，不编造。不要把 8 个任务作为单次 120 秒请求。

图片须由操作者提供或合法创建，仓库未附参考素材。纯文本路径可以不上传。若实际版本不支持某个输入模式或任务时长，记 BLOCKED 并保留具体报错；不可擅自虚构模型能力。

## 3. 视频检查和判定

逐镜检查而不只查看缩略图。记录实际镜头区间、每个相邻边界及所有关键失败的时间点，视频与音频都需审阅。判定 PASS / FAIL / UNKNOWN / N/A，不强制将每个不适用项记为成功。

- V01 镜头结构：A/B 机位、实际切点、是否出现多余镜头。记录目标与观察时间差，不虚构帧级容差；用户锁定精确帧时以其要求为准。
- V02 人物：脸、发型、服装、身体比例跨镜/跨任务一致性。
- V03 手与道具：持机手、占用、额外手指、物体位置、收纳/取回和固定锚点。
- V04 声画：发言者和话音内容、可见说话者同步、闭嘴 VO、未出现的嘴部标 N/A；J/L-Cut 的实际音频关系。
- V05 音乐与视觉：是否生成背景音乐、字幕、水印、虚假 UI、非指定文字；有疑问的声轨标 UNKNOWN。
- V06 连续性：各独立 Part 的首末状态、普通切镜可用性、选用转场真实剪点；没有特殊转场不扣分。
- V07 编辑时长：实测各素材实际长度、可保留区间、裁切/重叠及最终净时长；需要裁切而无余量时记录冲突。
- V08 叙事风格：镜头是否服务题材，节奏与情绪是否恰当；Classic 与 Adaptive 只在可比样本基础上定性比较。

## 4. 每次运行记录

将下述字段填入 examples/h3-validation-results.md 或另建含日期的结果文件，不覆盖原始测试证据：

Run ID；样本 ID；日期；模型版本/平台；任务模式；参数和种子；实际参考素材及上传顺序；输入需求；每个 Part 的完整 Prompt（或固定 commit 链接）；实际视频/音频文件位置；V01–V08 各项结果与证据时间点；实际素材及净成片时长；失败原因（模型能力/输入缺失/文本缺陷/剪辑限制/未知）；修复或回退；复测引用。

有授权的真实转场如果不匹配，使用普通硬切回退，记录原技巧 FAIL 以及回退是否通过；不能把回退成功算作原技巧成功。模型实际不按无 BGM、闭嘴、时间点等要求执行时，记录 FAIL 或 UNKNOWN，必要时简化方案或后期处理。

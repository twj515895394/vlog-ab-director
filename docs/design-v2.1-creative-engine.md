# Vlog AB Director v2.1 — 人物短视频题材与轻剧情创意引擎详细设计

> 历史设计记录：成片上限、素材预算和叙事路由已由 [v2.2设计](design-v2.2-editing-director.md) 扩展，原120秒/8任务不是现行限制；创意共创与确认机制不变。

> 设计基线：main 67de77323ec096335408d19d53570ca3f8bcec11（含 CRLF 修复）；前置 [v2 导演引擎](design-v2-director-engine.md)。2026-11-18。v2.1 为开发阶段名，正式版本发布仍受原实机验收门禁约束。

## 1. 背景与产品目标

v2 已解决明确需求如何拍、如何控制状态、如何装配 H3 Prompt。用户常常只有一个人物、一张图、一种审美偏好，甚至没有点子。v2.1 解决「拍什么」及「如何与用户共同找出值得拍的创意」。定位：**以人物为主体的电影感短视频创意与视听导演**（现行常规15–300秒；当时的时长范围已由v2.2取代）。Vlog 是一种表达形式而非唯一题材。允许轻剧情、弱剧情、非剧情视觉短片。人物的选择、体验、关系、情绪、生命状态或审美魅力主导作品，场景和道具为其服务，而非纯空镜拼贴。

目标：
- 从零构思：先给可讨论的差异化点子，不把完整剧本当作输入门槛。
- 人物驱动：尊重用户给定角色身份、关系、服饰世界观和参考素材；不凭图像推断未经说明的人物经历。
- 多轮共创：允许挑选、否决、融合、变体、细化、回退与确认；不在创意尚未定稿时输出完整 H3 Prompt。
- 可拍性：主动考虑短片容量、独立 15s 任务、角色/道具一致性、动作风险与后期限制。
- 无阻塞快路径：明确剧本/单次直接生成需求不被强行拉回创意讨论；只想要创意时不强制进入执行。
- 模块化：新增创意层，不更改 T01–T06 的导演路由本义、六字段、状态机、音频、转场或时间约束。

非目标：长篇剧情、复杂群像、长对白、多场武打、宏大特效作为默认核心；自动预测爆款/完播率；联网热点抓取、跨会话持久数据库、真实 H3 渲染或自动剪辑。用户可请求非核心题材，但明确简化或能力边界，不把它硬套成人物轻剧情。不得编造热度、模型成功率、素材或已测证据。

## 2. 决策与不变约束

| ID | 决策 | 规则 |
|---|---|---|
| CE-D1 | 人物为主体 | 美景/时尚/道具是人物表达的支撑；用户明确纯审美时可无故事冲突 |
| CE-D2 | 自由发散后收敛 | 默认先呈现3–5个真正不同的可执行概念；缺关键信息时最多先问一个针对性问题，非关键项可明确暂定 |
| CE-D3 | 创意确认门禁 | 选中题材不等同批准故事；讨论中的「喜欢A」不是生成授权；完整简案确认或明确委托推进才进入导演流程 |
| CE-D4 | 快捷路径 | 明确创作需求且直接请求成品：构建最小简案即可跳过讨论；完整剧本不强迫改写；仅求创意/剧本则停在对应产物 |
| CE-D5 | 可变而非机械 | 资料库为启发组合，不是固定故事、必须用转场、强制小反转或固定情绪曲线 |
| CE-D6 | 原 v2 硬约束（时长已由v2.2取代） | 现行0<T≤300秒、独立15秒任务、有限素材预算，净时长诚实核算；Classic固定6×2.5s；现有无BGM、参考资产、物理状态和转场规则不变 |
| CE-D7 | 证据与版本 | 创意QC+有限静态校验不证明实际生成效果；不升级正式版本号或虚构自然语言/H3 实测 |

优先级：用户本轮明确修改 > 已锁定且未被修改的用户约束 > 已确认创意 > 本轮可逆建议 > 库及默认值。冲突时提出来，不能静默覆盖。用户锁定题材可以覆盖创意层偏好；导演模式仍由 T01 按原规则决定，不从题材机械映射。创意层可以给建议，不擅自宣告转场已授权。

## 4. 入口分类和交付意图

先独立识别两个维度：idea_maturity（ZERO / CHARACTER_ONLY / VAGUE / READY），request_goal（IDEAS / DEVELOP / BRIEF / PROMPT / MODIFY）。输入「没有点子」即使说想做视频也属于 ZERO/IDEAS 或 DEVELOP；「给10个题材方向」只交付创意；「写完整轻剧情剧本，不要Prompt」停在简案/剧情；「这个故事直接生成30s Prompt」属 READY/PROMPT，跳过发散。仅图像输入不猜身份、关系和情绪；能观察到的服饰、造型、场景作为描述，用户说明优先。

| 入口 | 首轮操作 | 是否发散 | 退出条件 |
|---|---|---|---|
| ZERO | 根据明确约束/暂定人物给3–5条具体点子；未知人物时兼容不同主角 | 是 | 明确选中并确认细化简案，或委托直接推进 |
| CHARACTER_ONLY | 提取用户给定/可见人物特征，多方向设计人物情境，保留身份 | 是 | 同上 |
| VAGUE | 进一步提出2–4种发展方向，不抹掉已有点子 | 按需 | 形成可拍简案并获确认 |
| READY | 尊重完整剧本/明确日常或审美任务，必要时填可逆默认值 | 否 | 用户已经明确请求直接产出，或继续仅讨论 |

如果用户说「你决定、直接给成品」且允许创意委托，可内部构思→QC→交接，简短说明关键假设，不额外等待确认。如果要求只给创意、继续讨论，即使选中某提案也不能转入成品。用户明确的生成请求可作为确认，不需要机械再问一次。

## 5. 题材分类体系（内容方向而非拍法）

每条点子有一个 primary_genre，可另选 secondary_genres（建议0–2），并分别标记 story_structure、tone、relationship、camera_intent。题材与审美、人物关系、主/客观机位并非同一维度。以下为目录，详细卡片在题材库。

| 编号 | 内容方向 | 人物驱动力 | 常见记忆点 | 适配边界 |
|---|---|---|---|---|
| G01 | 日常生活 | 做一件日常小事，感受变化 | 生活动作的细节 | 不流水账 |
| G02 | 人物旅拍 | 人物探索未知地点 | 一次发现、体验、反应 | 风景从属于体验 |
| G03 | 情侣/陪伴 | 关系、互动、默契 | 同步动作、照顾、错位回应 | 不强设恋爱关系 |
| G04 | 情绪/治愈 | 内心状态变化 | 声音/道具/光的情绪反差 | 不强煽情 |
| G05 | 轻剧情微短片 | 单一事件或目标 | 触发、选择、结果 | 避免多条支线 |
| G06 | 人物审美/时尚 | 人物形象、动作、风格 | 视觉质感、动作呼应 | 可以完全无剧情 |
| G07 | 角色沉浸 | 虚构角色在其世界生活 | 世界观内的日常体验 | 不引入不合设定物件 |
| G08 | 人物微纪录片 | 职业/习惯/创作过程 | 一个代表性行为 | 不编造纪实人物事实 |
| G09 | 沉浸式 POV | 主角与镜头外观众互动 | 视线、邀请、回应 | A不等于主角自拍 |
| G10 | 视觉诗/艺术电影 | 人物与记忆/自然/时间关系 | 构图/象征/光影呼应 | 不堆无意义空镜 |
| G11 | 趣味反差 | 人物预期和现实的小落差 | 反应或小反转 | 不强低俗/羞辱 |
| G12 | 幻想日常 | 人物经历一个超现实假设 | 一个可拍的奇异规则 | 优先实景/剪辑表达，不靠任意魔法特效 |

可与古风、现代、半写实、写实、3DCG、柔光或高对比等风格组合。没有题材明示时先提出覆盖不同驱动力的具体方向，不把库整张表丢给用户。

## 6. 叙事、人物关系、情绪与种子资料库设计

叙事结构 S01体验、S02微目标、S03微事件、S04情绪递进、S05关系变化、S06探索发现、S07首尾呼应、S08沉浸观察、S09音乐视觉（音乐后期）、S10小反差/反转。一个主结构、最多一个辅助结构是推荐而非硬限制。节拍单元是叙事状态变化，不是固定镜头数。可直接无事件采用观察/视觉结构。禁止把每条作品强行做成开头反转、矛盾或痛苦经历。

人物关系库描述互动行为而非固定角色标签：独处/情侣/友人/家人/陌生人/职业关系/镜头外观众/虚构伙伴；每条含动机、互动小动作、视角、道具负载、关系变化及避免项。用户给定关系不得擅自改设定。多人物发言归属继续 T04。

情绪库使用初态→触发→中间反应→终态（或保持同一状态）的路径。表演由可见动作、节奏、视线、空间或现场声表达；旁白可选，不把心理说明当作必须口播。治愈、浪漫、怀旧、松弛、自由、好奇、喜悦、孤独、释怀、反差、仪式感/梦境等均可，避免无依据添创伤。

创意种子是可组合的一句情境，不是强制照抄故事：含触发、主角能做的事、记忆点、可能结构和生成风险。库覆盖各主方向，至少24种不同种子，优先小动作、可见物件、空间或声音触发。素材可替换，不重复固定耳机/咖啡/旧信。种子不声称真实发生、爆款或唯一创意。

## 7. 创意组合与多样性机制

输入层记录 confirmed_constraints / preferences / open_questions / available_assets / exclusions。硬约束先筛掉不合世界观、目标时长/复杂度、人物、关系、禁用元素、指定台词及素材冲突；未知素材仅标所需，不编造存在。用户要求指定主题则在主题内发散。

组合流程：
1. 锁定人物及明确约束，确定核心驱动力（关系、探索、审美、体验、微目标、情绪、趣味）。
2. 选主/辅题材、关系和人物目标（无目标的审美观察合法）。
3. 选择触发或视觉主题，组合一个主叙事结构和情绪路径、一个可见记忆点、结局方式。
4. 具体化人物行动、场景与因果，给 2–5 个节拍（长片可更多），避免无目的堆元素。检查实体道具/人物数量和复杂动作。
5. 做轻量时长/生成可行性检查，记录潜在参考图和后期需求，必要时降复杂度。
6. 构造候选指纹：genre+driver+trigger+structure+ending+motif。两条只改地点/服装/风格、核心事件及情绪走向完全相同属近重复，应重写；同题材下可在驱动力、事件、结构和结果中显著改变至少两个维度（用户要求同机制变体例外）。
7. 根据贴合度、人物主体性、记忆点、情绪/叙事清晰、生成可行性、方案差异作定性排序；默认不显示数值评分或声称预测流量。推荐一个并说明取舍，但保留用户选择权。

默认3–5个候选；用户要求数量优先。每条提案格式：稳定ID/标题、主方向、1–3句核心内容、人物驱动力或情绪变化、可见记忆点、建议时长范围、相对生成难度低/中/高及关键取舍。不是完整分镜、模型提示词或强制图像生成。用户只需点子时可更短。

## 8. 短片容量与可生成性

| 目标 | 建议节拍 | 常见可拍内容 |
|---|---|---|
| 15s | 1–3 | 单事件/单视觉主题/一次反应，留白 |
| 30s | 3–5 | 一个微事件，铺垫、触发、回应 |
| 45s | 4–6 | 一目标，多次连续体验 |
| 60s | 5–8 | 完整轻剧情或两阶段情绪 |
| 90s | 7–11 | 关系或探索逐步发展 |
| 120s | 8–14 | 明确核心主线、可分独立段落的微短片 |

非硬性镜数；配合原T02按 15秒独立任务与净时长计算，创意阶段不安排全局模型时间码、不承诺生成精确画面。建议15秒优先1–2个主要角色、1个主场景/事件；长片也避免无限加场景。复杂穿戴、手部交接、多个同时动作可变为硬切省略；高难度场景转场可提出后期选择但未授权不得应用。感情与记忆点优先由小动作、观察、停顿、表情、环境声实现。音乐卡点仅后期。对不可生成的核心戏剧点给保留原意的简化版本，不静默删除用户锁定内容。

## 9. 共创状态与交互协议

会话内维护一份 Creative Session（非跨会话数据库）：session_id、revision、request_goal、idea_maturity、stage、constraints、candidates（id/status/version）、active_candidate、feedback_log、draft_brief、confirmed_revision、handoff_permission。只依赖当前可用上下文；跨会话可请用户提供上次简案，不声称自动持久化。

状态：
- INTAKE → DIVERGE（零点子/人设）或 DEVELOP（已有模糊创意）或 READY（明确直接生成）。
- DIVERGE 给差异提案，进入 DISCUSS。PICK/LIKE 只聚焦，不发放生成授权。
- DISCUSS/DEVELOP 接收用户反馈：EXPLORE_NEW、REFINE、VARIATE、MERGE、REJECT、COMPARE、CHANGE_CONSTRAINT、UNDO；建立新 revision，保留来源ID及排除原因，回退不覆盖当前硬约束。
- DRAFT_BRIEF：输出简明可审核的创意简案，用户可编辑。需要进一步讨论时回 DISCUSS。
- CONFIRMED：用户明确同意当前简案或明确委托推进。只有当前 revision 匹配才有效。
- HANDOFF：创意QC通过且 request_goal=PROMPT 或明确要求进入制作，才进入 T01。只要简案/剧本时停在 CONFIRMED 或 DRAFT_BRIEF，不输出 H3。
- REOPEN：用户修改核心人物、事件、关系、情绪或时长等影响简案的条件时，撤销旧确认，重新QC和确认；用户同步明确「直接按新要求生成」可直接授权本 revision。只修改已确认镜头语言/局部呈现且不动创意，沿现有 T01–T06 修改并重检。

确认语义不是固定关键词：讨论中「喜欢B」「就这个方向先聊聊」不够；「B作为最终创意，直接生成30秒Prompt」足够；「你决定一个方案并直接生成」属于委托。模糊的「OK」结合上轮具体问题：如果上轮问是否定稿进入制作，则可确认；如果只问偏好，不得推断制作。不要反复索取已知信息。每轮聚焦下一步，提供具象变体/组合而不是重复题材列表。不预设用户必须经过多少轮。

回退/修改协议：用户说不要某元素记录为 exclusion；新提案不得无故复活。融合A/B时说明保留的原始机制，检查因果而非两段硬拼；变体保留明确不变项。用户说都不喜欢时从至少两个新的驱动力重新发散，不责怪用户。比较时只展示有实质差别的维度（情绪、关系、记忆点、难度、时长）。用户明确只要灵感可保持在 DISCUSS，不催确认。

## 10. Creative Brief 与 Director Brief 契约

Creative Brief 为内部或可审核的人物创意简案，非 H3 顶层键。字段：
- brief_id, revision, status=draft/confirmed, confirmation={kind:explicit/delegated/direct_ready,revision}（draft无确认），request_goal。
- title, logline, primary_genre（可 custom）、secondary_genres、primary_goal/driver、story_structure、characters（稳定character_id、用户确认身份/关系/服装、未知项）、setting/world（时间地点/年代）、premise_or_visual_theme、beats（顺序、人物行动、目的、可见结果，不固定时码）、emotional_arc、memorable_moment、ending。
- duration_target_s（暂定可空；交接时有0<T≤300秒的可行目标或解释默认15）、aspect_ratio（用户明确或标暂定）、camera_intent、director_mode_lock（如有）、dialogue_intent（含逐字锁定文本）、audio_plan_intent（生成无BGM；后期音乐仅可选）、transition_preference（未授权默认仅建议）、assets（global_id、类型、可用/待提供，未提交不写 Picture N）、constraints、preferences、exclusions、assumptions、risks、open_questions、creative_qc（hard/soft/证据）。

最小交接：标题/主题、主角、场景或世界、清楚的核心事件/视觉主题、节拍与结尾（观察式可开放）、目标时长、明确硬约束/音频/资产、当前确认与创意QC。其余字段可不适用或暂定，不用伪造句子。不要把简案内部键放进六字段。

映射到 T01：
| Creative Brief | Director Brief |

## 11. 创意质量门禁（与 T06 分离）

HARD：CR-H01 用户硬约束/世界观/人物不变；H02 明确人物主体性（非核心请求可说明边界）；H03 无素材/真实经历虚构；H04 时长、剧情负载、独立任务约束可行；H05 因果/视觉主题成立、无矛盾；H06 无BGM与转场授权保持；H07 创意确认与交付意图正确；H08 简案版本与交接完整、无伪 H3 字段；H09 排除项/确认过的约束不被反复覆盖。创意讨论阶段处于 draft 不属错误，仅交接门禁。无法解决硬错误时停止交接并说明，不能用软质量抵消。

SOFT：CR-S01 记忆点；S02 人物情绪/动作可见；S03 方案差异度；S04 叙事密度；S05 避免套路/无必要冲突；S06 生成/剪辑复杂度；S07 氛围、视觉与声音统一；S08 用户反馈响应及选择便利；S09 真实性和生活质感；S10 结尾合适而非必反转。用定性 PASS/REVIEW/UNKNOWN/N/A，自查不等同真实模型测试。修复核心创意需再次获得当前 revision 授权，其他层风险说明即可。最终 Prompt 仍必须执行独立 T06。

## 12. 回归、示例与验收

四个完整会话样例：零想法→多个方向→用户挑选→融合/调整→明确简案；角色/素材→多个情境（无图引用虚构）；模糊点子→变体、否决重构；确认简案→T01 映射→完整独立H3示例。至少覆盖 READY 直通、只要创意不生成、模糊 OK、授权直出、排除项、当前revision确认、重开、人物主导、单纯审美、古风无手机、15/30/120秒、无BGM、参考图、suggest_only、中文VO、Classic硬锁等正反例。行为用例标 NOT_RUN，只有真实运行才改状态。有限脚本检查结构化状态/确认契约、库ID与覆盖、跨平台换行、引用文件与旧模板冻结。原 tests/qc-check.mjs 不改，保留用户 CRLF 修复；执行其核心或真实 Node CLI 并准确记录方式。

验收门禁：G-A 设计与计划先提交；G-B 创意规则及资料库完整；G-C 两入口接入且共创门禁明确；G-D 示例与可重复静态回归、原 v2 回归通过；G-E 实际加载 Skill 多轮行为/真实H3测试另行验证，不擅自升正式版本。没有实机环境时诚实标候选。

## 13. 可维护性、风险与扩展

题材库由稳定 G-ID、叙事 S-ID、种子 K-ID、关系 R-ID、情绪 E-ID 组合；样例仅引用明确ID，不把库转成只有固定模板的推荐清单。增加新题材/种子不需要重写 T01；为每个新增方向补可见行动、结构、风险和回归。每轮只读取必要内容，默认不展示内部状态表。用户会话上下文不足时明确缺失而非假装记忆；多轮讨论避免被单轮模型自动生成倾向提前推进。版本描述由真实验收状态决定。后续可按用户另行要求扩展趋势研究、个人创意资产库、发布平台标签，但不在本期实现。

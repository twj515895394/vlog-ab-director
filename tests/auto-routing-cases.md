# T01 Auto 导演策略路由：行为回归案例

> 级别：**规范静态回归（不依赖真正的视频渲染）**。  
> 状态：T01 已将 Auto 路由约定纳入 `SKILL.md` / `SKILL.cn.md` 并创建 `references/director_strategy.md`；这些是**对基于文本的 Skill 的执行指令**，不代表存在程序化分类器。  
> 依据：[`references/director_strategy.md`](../references/director_strategy.md)、[`tests/regression-matrix.md`](regression-matrix.md)；T02 动态时间轴、T05 非 Classic 完整模板、T07 模型实机依旧待实施。

## 1. 策略优先级（可作为人工验收 oracle）

1. 用户直接点名模式或严格六镜/2.5s/交替 → 选用户明确模式；互斥硬约束需要告知冲突；
2. 明确以外部镜头、人物美学或氛围为主，减少自拍/对白 → Cinematic-led；
3. 旅行探索、情侣互动、微剧情、场景变化或自拍与环境自由配比 → Adaptive AB；
4. 只强调陪伴/对镜交流且不要求 Classic → Adaptive AB，提高 A 镜权重；**POV-led 暂不单独支持**；
5. 没有足够信号 → Classic AB 保守回退；
6. 世界观禁用手机时改变 A 镜实现方式，不强迫更换导演模式；
7. 时长上限 120s 与不强制转场、无 BGM 是跨模式硬约束；但 T01 仅识别需求，不替代 T02/T03B/T05。

## 3. 典型路由推演

### F02：旅行景色优先

- 有「旅行」「偶尔自拍」「多展现山海」等视觉目标，且没有固定六镜约束；
- Auto 判定 `Adaptive AB`，B 景别负担更重，但仍应存在有效的主观在场感；
- T01 **不宣称**已实现不等长时间分配；时间与模板由 T02/T05 承接。

### F03：纯氛围

- 明确「人物电影感、低饱和、少口播」；
- Auto 判定 `Cinematic-led`，不自动加入开场直视打招呼或强制三镜自拍；
- **仍然无 BGM**，镜头可留自然声音与环境 Foley；后期音乐由用户自行添加。

### F24：固定镜头优先于视觉风格

- 既有「严格六镜 2.5s」又有「电影质感更高级」；
- Auto 必须选 `Classic AB`；视觉风格修饰并不等于允许改变镜头结构；
- 可直接复用 T00 两套 Classic 参考用例的镜序与时间码。

### F28：互斥用户硬约束

- `Classic AB` 定义 A1-B1-A2-B2-A3-B3，却同时要求完全没有 A 镜；
- 正确输出是说明约束冲突并询问哪一条优先，而不是暗自选择 Cinematic 或删除 A 镜；
- 该冲突判定与普通题材推断不同。

### F29/F34：可没有任何神转场

- 转场推荐必须是按故事与拍摄条件的可选判断；
- 只是提出 T01 的 `transition_policy=OPTIONAL`，不能擅自实施 T03B 的特殊出镜/入镜技巧；
- 自然硬切仍是合格结果。

## 4. 静态检查点与阶段归属

- `SKILL.md` 和 `SKILL.cn.md` 都有 **默认 Auto 的步骤 0**、3 种正式路由、用户硬约束优先、Classic 镜头结构不可变、无手机世界观和无 BGM 规则；
- 仅 `Classic AB` 强制固定六镜、每镜 2.500s；
- 二者都引用同一份 `references/director_strategy.md` 作为路由规则源；
- 具备 F01/F02/F03/F04 与额外 F23–F34 的输入与预期决策；
- **现阶段验证的是文档内容与规则一致性**，不是 LLM 对每种自然语言输入的实际执行成功率，也不是生成视频效果；
- 下一 Ticket T02 才实施具体的可变镜头时间分配，后续 T05 才完善相应成品 Prompt 模板；**不得提前将 F05–F22 标成已通过**。

## 5. 手动验收建议（当前非实机）

将第 2 节每条输入交给加载了此 Skill 的模型，比较输出中的模式选择与理由是否和表格一致；如果遇到模棱两可的结果，先补充路由规则和冲突优先级，而不是直接引入关键词分数。当用户明确固定 Classic 时，再用 T00 的 15s/30s Prompt 检查是否回归旧时间轴与六段式结构。

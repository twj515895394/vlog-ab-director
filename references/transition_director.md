# Vlog AB Director v2：T03B 场景驱动的创意转场导演

> **状态：T03B 已接入的文字导演规则与交接决策逻辑**。本文件不是视频剪辑程序、AI 视频模型原生参数，也不证明任何复杂转场已经在 MiniMax H3 实机成功。
>
> 技巧来源：[46 种摄影与剪辑技巧库](../docs/transition-techniques-library-v2.md)；前置规则：[T01 策略](director_strategy.md)、[T02 时间预算](timing_engine.md)、[T03 连续性交接](continuity_handoff.md)。  
> 后续边界：T04 声画规则已接入 [audio_director.md](audio_director.md)，T05 已接入所选两端镜头的正式多 Part 六字段文本装配，见 [H3 Adapter](model_h3_adapter.md)；T06/T07 进行更完整的 QC / 实机验收。

## 1. 总纲：没有特殊转场也是正确的导演选择

**转场是基于具体场景的可选导演建议，不是「每个 Part 都得安排神转场」。**

- 任何多 Part 边界都**先比较普通硬切**是否已经清楚、自然、保留节奏。无需特殊转场时直接给出 `none`，不因 任意≤300秒长度而改变。
- **Auto 默认只提出有充分依据的建议**，通常为 `suggest_only`，**不自动改写原本的前 Part 尾镜与后 Part 首镜**。
- 只有**用户明确选用了技巧**（如「用水池穿越」「这个边界采用甩镜」），或**用户在创作需求中明确委托导演实际设计并使用适当神转场**（如「有合适的你直接帮我安排」），才允许进入 `planned_pair`；即使已被授权，也只应用真正适合的边界，仍可全部 `none`。
- 用户说「只建议、不要应用」→ `suggest_only`；用户说「不要任何特殊转场」→ 所有边界 `none`，且不能附加暗中运镜改造。
- 用户指定某种技巧但场景不支持时，**不能编造道具、人物动作、景别或可控模型能力来假装实现**；解释冲突，提供替代技巧或 `none`。不宣称 H3 可跨独立任务自动生成无缝一镜到底。
- 不推荐淡入淡出、交叉叠化、模板闪白、数字故障叠加或无动因的花哨软件转场；只采用**实拍构图、真实动作、运动/遮挡/光学条件和剪辑切点**。自然真实遮挡、运动模糊及失焦可作为隐藏硬切的素材条件。

**概念区别**：T03 的 `cut_ellipsis` 是两镜之间省略合理物理动作；T03B 的特殊转场是额外设计的**拍摄/剪辑连接技巧**。前者合法不代表必须有后者。

## 2. 输入：按实际播放边界独立评估

读取实际保留剪点两端镜头的：
- `story_boundary`：同一动作/同一地点、普通地点切换、时间跳跃、情绪转折、视觉隐喻、新章节等；
- `narrative_value`：特殊技巧是否帮助理解、突出主题或制造合理惊喜，还是打断人物情绪/对白；
- `camera_constraints`：导演模式、既有镜序、机位高度、运动方向/速度、景别与构图、用户锁定镜头；
- `match_elements`：真实存在的遮挡物、门洞、前景人物、同形/同色物、相近纹理、水面、连续动作等；
- `T03_continuity`：人物身份/服装、左右手、持机状态、道具 `prop_id`、固定场景锚点、允许的时空跳跃与参考图列表；
- `T02_editorial_budget`：每 Part 15s 局部镜长、可剪的入/出画余量、最终净时长要求（最多300s）；
- `user_transition_preference`：none / 只建议 / 指定技巧 / 明确授权导演按需实际应用；
- `audio_constraints`：可用现场环境声、Foley、人物声音；生成阶段严格无 BGM。

**没有可匹配的素材或可信的画面锚点时，选 `none`；不要为「技巧数量」硬塞镜头。**

## 3. 决策流程：先否决，再建议，最后才成对应用

按以下顺序执行，**对 P1→P2、P2→P3 …… P7→P8 的每个边界都单独处理**：

1. **硬否决**：用户要求不使用特殊转场 → `none`；当前是强情绪/对白/动作连续状态、特殊技巧会改变用户锁定的镜头、缺必要的真实匹配元素、或会导致无法解释的物理状态矛盾 → 倾向 `none`。
2. **硬切对照**：普通硬切能够自然连接时，先保留原样；只有技巧提供清楚的**额外叙事价值**才继续评估。无需显示一大串无关推荐。
3. **选择技巧**：从技巧库的 OC、CM、AC、GM、PT、OT 类中检索与本边界真的相关的候选；优先相对简单且有清晰剪点的技巧，最多推荐 1–2 个。风险 L/M/H 为**设计预估而非模型成功率**。
4. **可行性筛查**：检查两个独立视频生成任务是否能分别获得必要镜头；评估镜头运动方向/速度、遮挡覆盖、动作相位、人物身份、左右手与物理状态、参考图上传、场景跳跃是否吻合；无法对齐即回退。
5. **时长与产能约束**：不得修改用户锁定的 Classic 6×2.500s 镜头时间码；对已知的剪辑裁切计算 `net_final_s`，无裁切时不能无依据扣减；若精确目标时长 但需要裁切而没有素材余量，标 `LENGTH_FEASIBILITY_CONFLICT`，提供普通硬切或调整净时长等可行选项。
6. **权限判断**：如果用户只要建议或未授权调整镜头，输出 `suggest_only`；若用户明确指定/授权实际应用、筛查通过，输出 `planned_pair`。如不适用仍为 `none`。
7. **文字输出**：默认主输出仍是可复制 H3 Prompt；`suggest_only` 只在 Prompt **外部**附短建议，不偷偷改镜头；`planned_pair` 才更新两段镜头规划，向 T05 传递完整双端镜头规格和编辑说明。

### 3.1 三态协议

| 决策 | 应写什么 | 不能做什么 |
|---|---|---|
| `none` | 记录边界和「自然硬切更合适」的内部依据；无需给用户大量说明 | 强制安排特色转场、要求拥有 `transition_id` 或双端转场镜头 |
| `suggest_only` | 1 个（特殊情况至多 2 个）合适的技巧 ID、叙事理由、建议的双端拍法大意、风险；**输出在 Prompt 外** | 修改任何前 Part 尾镜/后 Part 首镜、变更时长/道具/参考图、假装已采用 |
| `planned_pair` | 完整的出镜/入镜镜头、切点/后期操作、动作/遮挡/方向匹配、状态与资产继承、时长损耗、风险和回退 | 只写「无缝神奇穿越」、单边设计、引入未授权的新主角/新道具、破坏固定 Classic 6 镜 |

**“推荐”与“执行”必须区分**：Skill 可建议使用，不能在 `suggest_only` 状态下把建议写进 H3 `detailed_description` 当成已发生的镜头动作。

## 4. 六类拍摄/剪辑技巧的搜索路由

所有 ID、定义、场景风险以及配对方式，以 [技巧库](../docs/transition-techniques-library-v2.md) 为准。**不要仅看 ID 关键词机械匹配**。

| 类别 | 风格/叙事触发器 | 一般不推荐的情况 |
|---|---|---|
| `OC01–OC07` 遮挡隐藏切 | 真实人物、树干、立柱、门框、包、车体等进入前景；可达满幅遮挡 | 遮挡太小、遮挡物无对应项或正在进行重要对话 |
| `CM01–CM08` 运镜接力 | 想从一个地点有节奏地接到另一处，且两侧运镜方向/速度可以匹配 | 情绪极安静、肢体运动已复杂、甩镜将破坏定位 |
| `AC01–AC08` 动作匹配 | 迈步、转身、举杯、穿门等连续且相位可对齐的动作 | 人物姿态/手/道具无法继承，或动作过危险 |
| `GM01–GM08` 形状/构图匹配 | 杯口→圆形水波、门框→另一门框等真实视觉关联 | 需要物体真实魔法变形、无共同形状 |
| `PT01–PT08` 门户/空间穿越 | 水池、倒影、门洞、隧道、镜面等有意识的时空跃迁或梦境联想 | 写实作品中要求不可能的无切跨空间移动或缺第二段对应纹理 |
| `OT01–OT07` 光学/声音辅助 | 真实失焦、反射、影子、时间跳切；J/L Cut 可辅助画面连贯 | 仅靠套模糊/纯声音就宣称有摄影神转场 |

**OT06/OT07 是辅助声画剪接**，并非用户期望的单独摄影神转场。声音桥的具体语义遵循已接入的 [T04 Audio Director](audio_director.md)；旧 `<scenetrans>` 标签尚待实机验证，不能因为 L-Cut 就附加 BGM。

## 5. `planned_pair` 双端镜头契约

当 `decision=planned_pair` 时，必须同时填写：

| 字段 | 内容与硬性检查 |
|---|---|
| `boundary_id`、`from_part`、`to_part` | 须为真实播放相邻的镜头/素材任务 |
| `story_reason`、`transition_id`、`risk` | 叙事作用清楚，`transition_id` 存在于 46 技巧库中 |
| `outgoing_shot` | **出点镜头**（通常连续任务末镜）：原镜头 ID、机位/景别、人物/道具状态、摄影机运动、最终可剪姿态或遮挡状态 |
| `incoming_shot` | **入点镜头**（通常连续任务首镜）：实际局部剪入位置及镜头ID、起始可匹配的构图/遮挡/动作/方向，再揭示新场景 |
| `cut_basis` | 可被剪辑师查找的真实剪点：满幅遮挡、运动模糊峰值、动作相位、形状/构图对应、反射峰值 |
| `matching_constraints` | 运镜方向与节奏、主体位置、颜色纹理、几何轮廓、动作相位、两端机位高度及必要的连续性 |
| `physical_handoff` | T03 的 `exit_snapshot + events + allowed_changes + entry_snapshot`；出现时空跳跃时明确哪些物理状态保留/不保留 |
| `assets` | 两个 Part **分别上传**当前需要的角色/场景/道具参考，局部 `Picture N` 从 1 编号，无无效引用 |
| `edit_plan` | 精确的可剪画面条件、裁切需求及后期可能的调速、局部遮罩、音效同步；**不可声称模型会自行自动拼接** |
| `duration_budget` | 记录每端 `edit_in / edit_out`、预估有效时长、`net_final_s` 与目标对比；仅以实际确认的裁切损耗更新净时长 |
| `audio_bridge` | 环境音/对白/画外音/Foley 可衔接；生成阶段无 BGM，`non_diegetic_music: N/A` |
| `fallback` | 同场景低风险动作/构图匹配或普通硬切；高风险 PT/复杂 CM 必须提供可执行回退方案 |

### 5.1 既有 T02/T03/Classic 约束

- 不能增加 Classic 的第七个镜头；不得擅自修改 Classic 每镜 2.500s，也不能强迫用户改写已经确认的六镜剧情。若已有尾镜/首镜无法承担转场，**保持原镜头并只建议，不得强行用 `planned_pair`**。
- Adaptive/Cinematic 可以在**满足用户要求、总镜长精确 15 秒、状态连续**的前提下调整两个边界镜头内容；不因神转场挤掉重要台词/动作。
- 每个 Part 独立生成；不能要求 H3 一次「穿越水池从 Part 1 延伸到 Part 2」。
- 不改变角色身份、保留的服装/道具、手机持有手与当前上传参考图映射。若转场需要新参考素材，只能列出**用户需要真实上传的新素材**，未上传不得直接在 Prompt 中写 `<Picture N>`。
- 即使使用视觉匹配导致地理位置改变，T03 `location_jump` 仍需要说明携带物与旧场景固定锚点去向；镜头相似不等于物理状态可以瞬移。
- 镜头接续需有真实剪点。模型 H3 的动作/运动模糊/水纹是否够稳定，必须留给 T07 实机检查。

## 6. 典型边界输出示例（均为内部规划，非完整 H3 Prompt）

### 6.1 安静对话：`none`

- `P1→P2`：两人同一间客厅，正进行重要情绪表达。
- 决策 `none`；普通硬切继续对话或保留声音连接。
- **无需** `outgoing_shot` / `incoming_shot` 转场字段；T03 仍检查人物道具状态和说话者归属。

### 6.2 旅行街景→树林：`suggest_only`

- `P2→P3`：街边确实有树干，下一地点有相近树干/柱状前景。
- 推荐 `OC02`（树干/立柱遮挡）。建议上一镜同向平移至树干完全遮满、下一镜从相似树干后同向移出；切在真实遮挡峰值，预计 L 风险。
- **不修改原 P2 尾镜和 P3 首镜**，没有授权时只在 H3 Prompt 外提供简短建议；也不自动扣减净时长。

### 6.3 用户明确采纳甩镜：`planned_pair`

- `P3→P4`：用户要求用水平甩镜从街道接到海岸，两个任务均预留摄影机运动。
- 技巧 `CM01`、风险 M；出镜右向甩镜直至场景模糊，入镜**也必须右向甩镜**并从模糊减速显露海岸；切点为两段同向运动模糊峰值。
- Handoff：人物/手/道具延续，`location_jump` 明确跨地点；两端分别上传相应场景素材；编辑时只在确认有必要时裁切，预估净时长不得擅自冒充已经精确成片。
- 如果 H3 模糊运动纹理无法稳定匹配，回退普通硬切或更稳妥的前景遮挡切。

### 6.4 水池穿越另一场景：`planned_pair`（有明确授权时）

- `P4→P5`：用户要求水池/溪水穿越到另一个地点；技巧 `PT01`，风险 H。
- **Outgoing**：前 Part 最后一镜摄影机**安全靠近浅水面**，波纹与气泡覆盖画幅，记录水体颜色、纹理、运动方向，最终切在**水纹覆盖最大**的合理帧。
- **Incoming**：后一 Part 第一镜从**相近水纹/气泡占屏的状态**开始，摄影机沿匹配方向向上离开水面，再揭示海滩或湖岸；镜头由摄影机完成，不让演员危险潜水。
- **Cut**：在相似水纹覆盖帧之间执行**硬切**，可以有水声/Foley，绝无 BGM；若水泡不稳、两任务材质/构图不匹配，降级为 GM03 水面纹理匹配或直接硬切。
- **预算**：先评估两端镜长是否足够完成接近/退离水面的动作，再记录可能剪掉的尾帧与首帧；**8×15s 名义等于 120s 不代表剪后仍精确 120s**。
- 写实故事中应明确这是后期剪辑造成的地理跳切，**不声称模型能真正贯通不同空间的一镜到底**。

## 7. T03B 检查门槛与回归口径

**适用于所有边界的硬规则**：
1. 用户没有授权/不需要时，不应修改边界镜头；`none` 和 `suggest_only` 均为合格结果；
2. 没有合适题材理由就不能推荐技巧，不能按任何任务数强制配置转场；
3. 用户明确不要特殊转场时所有边界 `none`；只要建议时只用 `suggest_only`；
4. 禁止淡入淡出、交叉叠化、模板闪白/插件特效冒充神转场；
5. 仍遵守 T01 模式、T02 镜头时间闭合、T03 人物手/道具状态、当前任务参考图映射及无 BGM 规则。

**仅当 `planned_pair` 时的硬规则**：
1. 出/入镜头双方定义，剪点/运动/遮挡/动作对应明确；
2. 不破坏 Classic 2.500s × 6 镜和用户锁定镜头；必要时应降级 `suggest_only`；
3. T03 交接的物理变更有事件，不强行把新地点说成同一瞬间；
4. 高风险技巧必须有稳定性风险与普通剪切回退；
5. 对已知裁切、重叠等成本重新核算净时长；精确目标但素材不够应报告冲突。

**软性评估**：
- 是否为了炫技拖慢故事/挤掉有效人物表达；
- 是否多次重复同类型擦镜或甩镜导致观感疲劳；
- 复杂拍摄动作是否不符合角色年龄、场景安全、自然电影感；
- 镜头信息是否足以让真正的后期剪辑师找到合理切点；
- 如果全片完全不用神转场，**不应以「技巧太少」扣分**。

**阶段边界**：T03B 当前只提供可执行的**自然语言导演规则、双端规划契约和静态样例**；没有新增视频编辑插件、没有真正加载 Skill 的对话执行报告，也没有 MiniMax H3 实机转场成功率。T05/T07 分别负责 H3 完整多 Part Prompt 与真实视频效果。

实际剪辑边界而非任务编号决定转场；连续链保持T03，非连续依据Story时期。普通连续性剪辑可以自动选择，特殊双端仍采用三态授权。[转场适配](editing/transition_adapter.md)。

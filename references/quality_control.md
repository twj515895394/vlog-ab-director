# T06 统一质量门禁（Quality Control）

本文件是运行 Skill 时的必经交付检查，不是把全部检查表塞入用户 Prompt。文本合规与真实视频质量分别判定。所有完整 Prompt 先经过本文件；任何 hard 未解决不得称为合格成品。

## 1. 检查输入、输出及证据

内部记录用户锁定的题材/语言/模式/画幅/时长/台词、T01 director_mode、T02 每段时间表与编辑账本、T03 状态和每个实际上传 manifest、T03B 每边界决策、T04 音频计划、T05 实际输出六字段文本。没有数据时标 UNKNOWN，不猜测已上传资产、生成模型能力或已渲染结果。

每项检查用 PASS / FAIL / UNKNOWN / N/A、定位（Part、Shot、字段或边界）、依据、修复方案记录。N/A 只用于确实不适用的条件，例如没有台词时的 VO、none 边界的特殊转场双端字段。UNKNOWN 不得当作 PASS；缺关键输入无法保证硬约束时需说明限制，必要时向用户确认。已知模型效果未验证属于实机未知，不阻止合规文本交付。

证据等级：
- S：可重复的结构/算术检查；仓库脚本 tests/qc-check.mjs 仅执行可解析规则及确定性结构化案例。
- L：逐镜/边界人工或语言模型语义审查，有明确文本依据与输入快照；不能由关键词命中冒充。
- V：实际 H3 视频/音频样本核验；只有真实生成并查看结果才能通过。
- E：用户报告的单例经验，保留中文 VO 实测证据但不泛化为 V。

## 2. 硬门禁（保持设计 H01–H11；扩展 H12–H15）

| ID | 检查对象 | 不通过的典型原因 | 修复规则 |
|---|---|---|---|
| H01 | 本地 0–15s 时间、镜号、区间 | 空档、重叠、零长、超时、错用全局时间 | 重新算累计边界，所有镜时长正数；Classic 不改固定切点 |
| H02 | 当前 Part 上传 manifest 与引用 | Picture 3 无图、全局/局部混淆、T2VA 引图 | 先定义真实上传顺序再替换所有引用；未使用的已上传图片不是硬错误 |
| H03 | 人物身份、说话者、持机者和世界观 | S1/S2 串位、古风造手机、无事件换脸 | 恢复角色 ID 与世界设定，逐角色检查可见/实际持机 |
| H04 | 左右手及互斥道具 | 同手同时持机与咖啡、同一实体同时两处 | 拆时段/切镜、换空闲手或简化动作，重新推导入出状态 |
| H05 | 道具生命周期、固定锚点、相邻镜/Part | 道具瞬移、无事件消失、固定锚点跨城 | 记录入/出状态与合法 cut/jump event；不得用特效掩盖 |
| H06 | H3 六字段、每段独立可用 | 缺字段、重复、空字段、伪顶层键、未替换占位符 | 按 adapter 重装配；禁止“同上”省略关键内容 |
| H07 | 对白标签、声源、口型与时间 | 同一角色同时开口闭嘴、中文 VO 被误拒、S1/S2 串音 | 绑定 speaker_id、可见口型及区间；尊重中文 VO，英文和 scenetrans 不必需 |
| H08 | 负向约束与画面需求 | 默认禁字幕块缺失，真实指定文字与全面禁止冲突 | 默认保留精确空行原块；仅明示实体文字时使用 Adapter 4.1 限定块，仍禁字幕/UI |
| H09 | D3 全局无 BGM | 非 N/A、正向音乐生成指令、音乐卡点塞 Prompt | 删除正向音乐请求，后期配乐只在 Prompt 外；明确无 BGM 否定语句合法 |
| H10 | ≤300s成片、有限任务预算、净长 | 超300s、单次长片、超用户预算或虚报净长 | T02与EDL核算，预算冲突明确反馈 |
| H11 | 可选特殊转场 | 未授权改镜头、只做单端、无剪点/回退、方向冲突 | none/suggest_only 不要求特殊字段；planned_pair 需要用户授权与双端/剪点/风险/回退并复核状态、时长 |
| H12 | Classic 或用户锁定镜头 | 改为五镜、错序、违背锁定画幅/台词/题材 | Classic 每段六镜 ABABAB、每镜2.500s；用户硬约束优先；互斥要求明确反馈 |
| H13 | 默认输出与内部规划分离 | 把状态表当 H3 字段、只给草稿或省略后段 | Standard/Multi-Part 完整 Prompt；仅必要清单/交接外置，Director Detail 按需 |
| H14 | 任务数量与独立性 | 计划多段却省略、分批不说明、引用上段音轨当可共享 | 核对成品数量及各自上传/局部时间；跨任务声音在后期拼接 |
| H15 | 证据与能力声明 | 假称模型精确切镜、所有转场实测通过、虚构成功率 | 区分 S/L/E/V，不虚构运行记录；T07 未通过则不升正式版本 |

## 3. 软性检查

| ID | 风险 | 优先调整 |
|---|---|---|
| S01 | 镜头没有信息增量 | 合并重复镜、保留叙事节拍 |
| S02 | 镜头动作时间不足 | 简化动作、延长非锁定镜头或硬切省略 |
| S03 | 景别和角度重复 | 选择有用途的近景/中景/空间镜 |
| S04 | 光线、服装、情绪无叙事理由变化 | 增加合理时间/地点跃迁，或保持原状态 |
| S05 | 旅行 Vlog 主观在场感不足 | 仅当题材需要时补 A/互动；Cinematic 全 B 合法 |
| S06 | 台词过密、表演动作占用发声窗口 | 减少台词、VO、留白；锁定逐字台词不可静默删改 |
| S07 | 过度复杂运镜/环境描述 | 减少同镜复杂任务、明确主体和稳定摄影机 |
| S08 | 转场炫技、重复或破坏情绪 | 优先自然硬切，建议与选用分离 |
| S09 | 参考图冗余或无图长片身份漂移 | 保持资产稳定、按实际素材给风险说明 |
| S10 | 场景文字、跨镜声画、精确帧点无实测 | 保留后期补救或更稳妥的替代方案 |

软性风险可解释但不能覆盖硬失败；不机械打分或编造模型成功率。零台词、全 B、零特殊转场不天然扣分。

## 4. 交付修复循环（每次重算受影响下游）

1. 检查用户约束和导演模式，再检查单段时间表、人物状态、资产、音频与每个边界。
2. 装配完整 Prompt，按 H01–H15 逐项检查实际文本与计划，优先修时长/资产/物理/声音矛盾，再修语法与输出。
3. 修复后重新核对全部受影响镜头与相邻 Part。改了镜长重新验证说话窗口、道具动作、双端转场和净时长；改了资产重编号当前任务所有引用。不得为了修局部引入新的硬错误。
4. 软性风险能合理调整就调整；不能调整且不违反用户硬要求时保留简短说明。
5. 完整 hard 检查通过才交付合规成品。若存在无法解决的互斥约束或素材输入缺失，明确指出并提供保守的可行方案，不捏造可执行内容。若需要用户选择才继续，只问影响结论的关键问题。
6. 默认只提供 Prompt、必要的素材/交接说明及重要风险或冲突。用户明确要求 QC 时附表：ID、Part/Shot、PASS/FAIL/UNKNOWN/N/A、依据、修复结果、证据等级。
7. 实机质量必须另行记录：不把内部自评、脚本输出、文字合规或 E 经验等同于 V。参见 docs/h3-validation-protocol.md。

## 5. 可重复测试

在仓库根目录用 Node.js 18+（无需 npm 安装）运行 node tests/qc-check.mjs。脚本验证六种模板的完整 Prompt、冻结 Classic 基线、样例 manifest、时间/字段/负向块以及结构化正反例；它**不是**任意自然语言的自动语义判定器。脚本 FAIL 时修复后再运行；脚本 PASS 仍需按 H03–H05、H07、H11–H15 等审阅实际任务的状态/语义及用户约束。参见 tests/regression-matrix.md。
v2.2 必须执行 [Editing QC](editing/editing_quality_control.md)，连续动作链严格T03承接，其他边界按Story版本核对；不能用剪辑能力擅改连续剧本。旧120s静态例为固定预算兼容。

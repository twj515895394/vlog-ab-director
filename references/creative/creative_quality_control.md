# Creative QC — 创意层独立门禁（C06）

目的：保证故事概念和交付状态合规，不判断真实H3视频质量。创意门禁先于T01；T06仍需独立执行。以当前输入、锁定条件、候选/简案、讨论反馈与确认版本为证据。任何未解决硬问题不能声称通过。

## 1. 九项硬约束

| ID | 检查 | 失败例 | 修复 |
|---|---|---|---|
| CR-H01 | 尊重用户硬约束/世界观/人物 | 古风禁手机却加自拍手机，改锁定角色 | 恢复用户约束，局部简化；互斥时反馈 |
| CR-H02 | 人物主体与目标 | 人物旅拍大部分纯空镜、无角色体验 | 把场景变为人物体验；明确纯景/产品非核心委托时允许 |
| CR-H03 | 不虚构输入/事实 | 给图中人编职业或关系当事实、假称图已上传 | 只用已知信息；创作提案注明虚构、素材待提供 |
| CR-H04 | 轻剧情容量及时长可行 | 15秒复杂四人剧情，目标150秒却声称可生成 | 降负载/提备选；15–120上限、≤8独立任务，T02核算 |
| CR-H05 | 叙事或视觉主题成立 | 道具突变、无原因的核心情绪反转、情节不连 | 重建因果或采用观察/视觉母题；无剧情不等于失败 |
| CR-H06 | D3与转场授权 | 音乐卡点进入生成声轨；建议转场被当已选 | 无BGM、音乐仅后期；未授权只建议/none |
| CR-H07 | 交付意图、确认门禁 | 喜欢B即出Prompt；只要点子却强行制作 | 保持DISCUSS/BRIEF；确认或明确委托且请求成品 |
| CR-H08 | 当前版本与最小交接 | 旧revision授权、简案缺人物/主题/时长、伪H3字段 | 重检真正当前简案；T01映射而非模型新字段 |
| CR-H09 | 反馈与排除项 | 用户明确排除咖啡又推荐咖啡；擅自替换锁定结局 | 过滤排除、保留锁定条件、修订有版本记录 |

未确认本来可以发散或展示draft，此时不是必须修复的硬错误；CR-H07/H08的确认子项在交接前生效。真正未知影响核心决策时标UNKNOWN并说明；可逆默认可明确暂定后继续。超出范围按原v2能力协商，不把用户明确的非人物需求强塞人物。

## 2. 十项软检查

| ID | 检查 | 改善方式 |
|---|---|---|
| CR-S01 | 记忆点是否具体 | 选可见动作、物件或空间反差，不只是唯美标签 |
| CR-S02 | 人物情绪是否能被观察 | 眼神/停步/呼吸/选择，非必须长解释 |
| CR-S03 | 候选是否真的不同 | 比较驱动力、事件、关系、结尾；不只换服装地点 |
| CR-S04 | 剧情密度适中 | 15秒一个核心点，留动作与情绪空间 |
| CR-S05 | 避免套路和强冲突 | 非剧情允许零冲突、无反转，避免无依据悲伤 |
| CR-S06 | 生成和剪辑负担 | 减少复杂交手、多人同步、过多地点；提示后期 |
| CR-S07 | 风格/声画/情绪统一 | 用用户指定美学和现场声服务人物 |
| CR-S08 | 反馈是否有实质价值 | 不反复问已知事项、不重复上一轮提案 |
| CR-S09 | 人物真实性和生活质感 | 代表性动作与动因，不机械模板化 |
| CR-S10 | 结尾是否合适 | 开放、完成、呼应、保持情绪、小反差均可 |

## 3. 修复与报告

逐项以PASS/FAIL/UNKNOWN/N/A（软检查也可REVIEW）记录简短依据；用户默认只看点子/简案及必要约束，不显示全表。硬错误先修复：缩短/去除无关事件、恢复锁定设定、声明素材未知、停止提前交付。改动核心创意需更新revision并由用户确认或明确续授权；软风险定性改善或披露。修复后复核其余条件与排除项，再交接。证据等级沿用T06 S/L/E/V；库完整与脚本检查仅S，自评不能替代实际加载模型多轮行为或H3视频。实机未运行明确NOT_RUN。
